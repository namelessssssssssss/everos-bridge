# 检索工作流代表性验证（2026-10-22）

范围是桥接规则、正文展开和任务内补查路径验证，不是跨模型正式benchmark。所有场景、历史记忆、错误码和现场数据均为合成，未向真实EverOS空间写入用例。主干基线为1c20b06，候选为0.8.0工作快照，逐文件SHA256与原始答卷/判分/日志manifest在仓外留存；后续的规则措辞澄清和私有原子状态写入另经回归复验。

## 对照

同一Codex CLI默认设置，不逐臂覆盖模型；CLI轨迹未提供独立模型版本指纹，因此不声称模型版本已严格锁定，也不据此做正式质量排名。主批4场景×4组16次，另补恢复场景×4组4次，共20次完成的隔离调用，均无技术失败。

## 分场景观察

- 新错误码：workflow/proactive在现场出现新标识后重新搜索，并展开记忆得到摘要外的处理条件和禁止重复的操作；auto未补查，policy多次搜索仍没有展开能力。
- 用户偏好：四组都能提出常见导出格式，但新工具两组进一步从正文恢复了单位要求。基线失分是历史细节缺失，不等于没有提出任何可行方案。
- 历史方案与现场冲突：四组均尊重当前不兼容约束，没有照搬旧方案；新工具两组查明历史仅适用于旧版本。完整判据分数与安全性结论分开看。
- 压缩后恢复（合成续接提示）：新工具两组重新取证与展开；workflow还主动调用memory_context recover。它验证的是恢复行为，不是真实超长上下文压力下的自动压缩质量。
- 无需历史细节的算术控制题：四组均直接回答且没有MCP调用；不能从这题声称Agent会主动遵守“每条消息首轮必查”，生产仍保留提问hook兜底。

20次调用轨迹中未见读取fixture源代码或其他非MCP工具的旁路获取。初次接入试跑因缺少只读工具声明被宿主审批策略拦截，单独保留为基础设施失败；修正声明后重跑，没有把该失败记成质量零分。

## 运行与真实接口验证

- 204项离线回归通过：分页、来源/截断、跨进程读取、跨身份拒绝、同问题复用/新问题与内容版本重读、压缩失效、关闭写入时恢复、关闭注入、无网络工具提醒等。
- 技能校验、Python编译、shell及Node语法检查通过。
- 真实EverOS只读链路：agentic检索→本机快照展开→会话问题记录成功，约38.64秒，7个快照，所读记忆正文809字符，无回退提示。未输出或发布真实记忆正文。
- 真实Codex CLI PostToolUse探针：只读fixture命令执行后，原生宿主调用新hook，生成一份本机提醒账本；未请求EverOS、未做权限裁决。其他宿主仅按协议和离线入口验证，不声明全部完成原生会话实测。
